# Firmware 14.10 userland capability matrix

Offline audit, 2026-10-24. Scope: the Hamidashi Creative Lua loader's **game process**, not a system process. This matrix treats a saved return value as evidence of that call only. A Lua helper's name, a loaded library, and a successful syscall dispatch do not establish authorization to change system Settings. The [AIO delete-race record](../../../AIO_DOUBLE_FREE_14_10.md) describes a repeatable race but lists kernel read/write as future work; an October 24 local control audit likewise found no kernel pointer and is not part of this staging branch.

The [curated evidence ledger](../../../RESEARCH_EVIDENCE.md#curated-scope-and-interpretation) explicitly supersedes earlier 43i/44a/45a native-execution interpretations and states that file hashes and banners do not authenticate a run. The native-execution row below therefore relies on later child-thread marker evidence, not those older claims. The corpus and this matrix are an offline audit of saved captures, not an independent firmware attestation.

## Working versus hypothetical

**Working:** Lua and native code in the game, process-owned memory, native syscalls subject to kernel authorization, enumeration of the game's modules, reads from selected ordinary interfaces, app-scoped files, and connections to three named service sockets.

**Unproven:** a Settings-facing service contract, a game-authorized system configuration write, a meaningful development/debug setter, reading or modifying the native Settings process, and kernel R/W. The presence of `libSceRegMgr.sprx` and `libSceSystemService.sprx` is the reason to inspect API contracts offline; it is not itself a capability to change the menu. No version-matched Settings service contract was identified in this branch.
